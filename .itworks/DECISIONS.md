- 2026-09-11 | kickoff confirmed: public wall and badge service for vibecheck closeouts at itworks.dev, one Go binary plus SQLite, no model calls, entries hidden until approved | why: Matt's written spec in WORKFLOW-PROMPT.md answers all six kickoff questions and marks the stack, host, and publish flow as decided; it is taken as the confirmation in his own words because the session runs unattended | instead of: n/a
- 2026-09-11 | versioning: build/patch auto, minor/major on Matt's word; ship tags ship-<YYYY-MM-DD> | why: kickoff default accepted | instead of: ad-hoc bumps
- 2026-09-11 | profile expert, inferred from "You are the PM" plus the owning-the-delivery contract | why: explicit handle-it instruction, not an inference from skill level | instead of: asking the calibrate question
- 2026-09-11 | deploy to pi3 and the itworks.dev domain purchase are deferred; tonight builds, tests, and stages only | why: Matt's message during the session | instead of: staging then waiting for a go tonight
- 2026-09-11 | badge color: red if any critical is open, else amber when the audit is 30 or more days old, else green; badge serves for pending and approved entries, 404 for hidden | why: the badge is the honest signal and must reflect the record even when it looks bad; a hidden entry gets no hosting at all | instead of: only serving approved badges (would break READMEs during the approval wait)
- 2026-09-11 | entry ids are 12 char random lowercase base32 from crypto/rand | why: pending entries are unlisted, so ids must not be guessable | instead of: sequential integers
- 2026-09-11 | admin handlers require the X-Authentik-Username header and a same origin Origin header on POST, in addition to Traefik forward-auth | why: defense in depth if the Traefik label is ever dropped | instead of: trusting the proxy alone
- 2026-09-11 | published tier and date: "audit" plus last_audit date when PROFILE.md has one, else "closeout" plus the closeout date; counts are whole-project from REVIEWS.md | why: the staleness signal should track the last time the logic was actually read | instead of: always sending the closeout sweep date
- 2026-09-11 | ISO dates (YYYY-MM-DD) are exempt from the no dash rule in visitor readable text | why: the audit date is data the badge and wall must show verbatim; the rule targets prose | instead of: a second display date field on EntryView
- 2026-09-11 | badge plates darkened to pass AA and the amber badge carries the word stale | why: three design judges measured the original plates at 2.5 to 3.4 to 1 against white text, failing on the one artifact that leaves the site; amber must not rely on hue alone | instead of: keeping GitHub style hexes
- 2026-09-11 | design direction: Ledger (round two), with Matt's fixes listed in docs/DESIGN-NOTES.md | why: Matt's pick after rejecting the round one editorial consensus as the common theme | instead of: Living Instrument (runner up)
- 2026-09-11 | plugin renamed from vibecheck to itworks (0.2.0); site repo is itworks-site on Gitea, plugin repo is itworks on Gitea and GitHub | why: vibecheck was crowded (two existing Claude Code plugins with the same install string, a 500 star MCP server) and Matt chose one brand for plugin and site | instead of: receipt, foreman, showyourwork
- 2026-09-16 | host itworks.dev on GitHub Pages: static site built by a Go command, entries are JSON files submitted by pull request, merge is approval, delete is hide; the Go server, SQLite, Docker and pi3 deploy are removed | why: Matt's call after the 2026-09-16 audit; a PR carries the submitter's GitHub identity and the server carried most of the confirmed risk | instead of: fixing the server findings and deploying to pi3
- 2026-09-16 | a pending entry has no badge until its PR is merged (404); closeout prints the badge markdown and says it renders after merge | why: static hosting has no unlisted state; pending was never secret, only unlisted | instead of: a grey pending badge committed by the submitter
- 2026-09-16 | accepted CRITICALs publish as a separate critical_accepted count and the badge is red when open plus accepted is above zero; the entry page shows the two numbers apart | why: the audit reproduced an accepted CRITICAL publishing as zero open and earning a green badge | instead of: folding accepted into critical_open
- 2026-09-17 | domain is itworks.build, bought on Spaceship at standard price; itworks.dev was a $350 a year premium name | why: premium .dev renews at the premium price forever and the brand is the plugin name, so changing the TLD beats renaming the plugin | instead of: itworks.dev, or a new brand such as closeout.dev with a full plugin rename
