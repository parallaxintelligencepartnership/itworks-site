What this is A ledger of apps that finished the vibecheck closeout review, printed in full.

What it is not A ranking, a score, a leaderboard, or a place where anything gets judged by a model.

Every line carries an audit date and a count of critical findings still open.

Anyone can say a build is done. This wall shows the receipt.

01

You build with the vibecheck plugin. It reviews the work, finds problems, and tracks which ones you fixed and which ones you knowingly accepted.

02

You run the closeout. That is the last review before a project goes out. It produces a summary with a date on it.

03

The summary gets published here, as is. Same columns for every app. No editing, no highlights reel, no way to hide the bad numbers.

04

You get a badge for your README. It shows the audit date and how many critical findings are still open. It updates when the ledger does.

The badge ages in public.

A badge is only worth the date printed on it. Scroll the ruler and watch one real badge get older. On day 30 the plate turns amber and puts the word stale inside itself, so the change is readable even if you cannot see the color.

The two plates above are the same badge at day 0 and at day 30. Motion is off because your system asks for it.

Time is only one of the two triggers. A critical finding that is still open turns the plate red on any day, including day 1. Age never outranks an open critical.

Three plates. One rule each.

The badge is an SVG you paste into a README. It is plain, it is flat, and it says what it knows. The badge can look bad on purpose. That is the point of publishing it.

Green plate, white text. The audit is under 30 days old and no critical finding is open. Plate color 1a7f37 with text ffffff, which clears AA at this size.

Amber plate, dark text, the word stale inside it. The audit is 30 days old or older. Plate color d29922 with text 1f1f1f. The word carries the state, so the color is a second signal and never the only one.

Red plate, white text. At least one critical finding is open. Plate color b3261e with text ffffff. The count is in the text, so a reader who cannot tell red from green still reads 1 critical open.

The whole rule, in order

  • If the open critical count is 1 or more, the plate is red. Nothing else can override this.
  • Else, if the audit date is 30 or more days behind today, the plate is amber and the word stale is printed inside the plate.
  • Else the plate is green.
  • The date in the plate is always the audit date, written as year, month, day.

Two lines, then build something.

Paste these into Claude Code. The plugin runs on your machine, against your project, and it is the thing that produces a closeout summary.

01 claude plugin marketplace add parallaxintelligencepartnership/vibecheck Adds the marketplace so Claude Code knows where to look.
02 claude plugin install vibecheck@vibecheck Installs the plugin. Run the closeout when your project is finished, then publish the summary.

Exactly what gets published.

Seven fields leave your machine when you publish. Here they are, in full, with nothing held back.

Display name
The name you want people to see. You choose it.
One line on what it does
A single sentence in your own words.
Source label
Either public or closed. If it is public you can add a repository link. If it is closed, the row still publishes and simply says so.
Audit tier and date
Which review produced the summary, and the day it ran, written as year, month, day.
Findings found
How many problems the review raised.
Findings fixed
How many you closed.
Findings accepted
How many you looked at, understood, and chose to live with.
Open critical count
How many critical findings are still open right now. This is the number that turns the plate red.

Nothing else is sent. No code, no file names, no logs, no prompts, no finding text, no model output.

The site never runs a model. It reads a small file of published summaries and prints them as static HTML from one Go binary. There is no scoring, no ranking, no analysis step, and no way for us to reach back into your project.

Rows are published by the person who built the app. You can update a row by running the review again, and you can take a row down. Nobody else can edit your line.

Parallax Intelligence builds and ships the vibecheck plugin for Claude Code. This wall is the public side of it.
